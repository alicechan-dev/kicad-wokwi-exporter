# KiCad 10 → Wokwi: экспорт `diagram.json`

Action Plugin для KiCad 10. Берёт схему открытого проекта и сохраняет готовый
`diagram.json` для симулятора [Wokwi](https://wokwi.com) в корень проекта (рядом с `.kicad_pro`).

```
wokwi_exporter/
├── __init__.py        регистрация плагина в KiCad
├── wokwi_exporter.py  весь код: нетлист, слияние, генерация JSON
├── icon.png           иконка кнопки на панели инструментов
└── mapping.json       ваш маппинг деталей — создаётся при первом экспорте, в репозитории его нет
```

## Установка (Windows, KiCad 10)

1. Скопируйте **папку** `wokwi_exporter` целиком в

   ```
   %USERPROFILE%\Documents\KiCad\10.0\scripting\plugins\
   ```

   В итоге должен получиться путь
   `...\Documents\KiCad\10.0\scripting\plugins\wokwi_exporter\__init__.py`.
   Если папки `scripting\plugins` нет, создайте её. Точную папку всегда покажет сам KiCad:
   **PCB Editor → Tools → External Plugins → Open Plugin Directory**.
   KiCad 10 также ищет плагины в `%APPDATA%\kicad\10.0\scripting\plugins\`.
2. В редакторе платы: **Tools → External Plugins → Refresh Plugins** (или перезапустите KiCad).
3. В меню **Tools → External Plugins** появится **Export to Wokwi (diagram.json)**, а на
   панели инструментов — зелёная кнопка.

macOS: `~/Documents/KiCad/10.0/scripting/plugins/`, Linux: `~/.local/share/kicad/10.0/scripting/plugins/`.

**Обновление плагина:** скопируйте поверх старых `__init__.py`, `wokwi_exporter.py` и `icon.png`.
Не удаляйте папку целиком: в ней лежит ваш `mapping.json`.

## Использование

1. **Сохраните схему.** Плагин читает файл `.kicad_sch` с диска.
2. Откройте плату проекта в **PCB Editor**. Action-плагины KiCad работают только в редакторе плат;
   печатная плата при этом может быть пустой.
3. **Tools → External Plugins → Export to Wokwi (diagram.json)**.
4. В окне отчёта видно, что экспортировано, что перенесено из прежнего `diagram.json`, какие
   детали пропущены и какие пины не нашли пару в Wokwi. Те же цифры печатаются в консоль
   (строки `[Wokwi] …`). Предыдущая версия файла сохраняется в `diagram.json.bak`.
5. В Wokwi откройте вкладку `diagram.json` проекта и вставьте содержимое файла.
   Скетч (`sketch.ino` / `main.py`) Wokwi нужен отдельно.

## Повторный экспорт и правки в Wokwi

Если `diagram.json` уже есть, плагин не перезаписывает его, а сливает с новым экспортом
(`SMART_MERGE = True`). Чтобы правки из браузера не пропали, скопируйте `diagram.json` из Wokwi
в папку проекта перед следующим экспортом.

| Что | Что происходит при повторном экспорте |
|---|---|
| Деталь или провод из схемы KiCad | Обновляется по схеме; поворот, ручные атрибуты и трассировка провода из Wokwi остаются |
| Позиция детали и цвет провода из KiCad | Остаются, если вы меняли их в Wokwi; иначе плагин ставит их заново (новая раскладка, новые цвета) |
| Деталь или провод, добавленные вручную в Wokwi (логический анализатор и т.п.) | Переносятся как есть |
| Деталь или провод, которые удалили или переподключили в схеме KiCad | Удаляются |
| Ручной провод к детали, которой больше нет | Отбрасывается, есть в отчёте |
| Ручная деталь, чей id совпал с новой деталью из KiCad | Переименовывается в `<id>_wokwi`, её провода переподключаются |
| Деталь из схемы, которую удалили только в Wokwi | Возвращается: источник правды для неё — схема |

Отличить ручное от устаревшего помогает файл `.diagram.kicad-state.json` рядом с `diagram.json`:
в нём то, что создал прошлый экспорт, вместе с позициями и цветами, которые поставил плагин.
Без него (первый экспорт после обновления плагина) переносится всё, чего нет в схеме, а позиции
и цвета из старого файла не трогаются; отчёт об этом предупреждает. Чтобы один раз разложить
и перекрасить всё заново, поставьте `RESET_LAYOUT = True` (или `--reset-layout` в командной
строке): детали, добавленные вручную в Wokwi, останутся на своих местах. Если нужно никогда
ничего не удалять, поставьте `DROP_DELETED_IN_KICAD = False`. Но тогда, например, после переноса
светодиода с D13 на D12 старый провод к D13 останется и замкнёт пины в симуляции.

Повреждённый `diagram.json` плагин не перезаписывает: экспорт остановится с сообщением об ошибке.

## Раскладка и цвета проводов

**Раскладка** (`LAYOUT = "grid"`). Плата ставится центром в `[0, 0]`, периферия — группами в
колонках слева и справа от неё:

* группа — детали, связанные сигнальной цепью: резистор и его светодиод, три резистора и
  RGB-светодиод, кнопка с подтяжкой. Детали, сидящие прямо на пинах платы, стоят столбиком
  ближе к ней, следующие по цепи — за ними;
* группы идут в порядке пинов платы и раскладываются на ту сторону, где колонка сейчас ниже;
  колонка выше `LAYOUT_COLUMN_MAX_HEIGHT` продолжается новой, дальше от платы;
* размеры деталей берутся из `PART_SIZES` (габариты SVG из Wokwi), между ними `LAYOUT_PADDING`
  px, поэтому LCD или серво не наезжают на соседей. Для неизвестных типов — `DEFAULT_PART_SIZE`;
* детали, которые вы сдвинули в Wokwi, и детали, добавленные там вручную, остаются на местах,
  а новые детали их обходят.

`LAYOUT = "schematic"` — взаимное расположение как на схеме KiCad (без учёта габаритов).

**Цвета** — по имени цепи KiCad (`NET_COLOR_RULES`), а если имя автоматическое
(`Net-(R1-Pad2)`) — по именам пинов на концах провода:

| Имя содержит | Цвет |
|---|---|
| `GND`, `VSS` | чёрный |
| `VCC`, `VDD`, `5V`, `3V3`, `3.3V`, `VIN`, `VBUS`, `VBAT`, `+12V`… | красный |
| `SDA`, `RX` (`RXD`, `RX0`, `U0RXD`) | зелёный |
| `SCL`, `TX` | синий |
| остальное | по кругу из `WIRE_COLORS` (`orange`, `purple`, `yellow`, `cyan`, …) в порядке пинов платы — соседние провода разного цвета |

## Как добавить свою деталь

Маппинг лежит в `mapping.json` рядом с плагином (в папке `plugins\wokwi_exporter`). Файл
создаётся при первом экспорте из встроенных значений по умолчанию и дальше читается при каждом
экспорте. Обновление плагина его не трогает. Чтобы вернуть значения по умолчанию, удалите файл.

```json
{
  "parts": {
    "LED": {"type": "wokwi-led", "attrs": {"color": "red"}, "pins": {"A": "A", "K": "C"}},

    "MyRelayModule": {"type": "wokwi-relay-module", "pins": {"VCC": "VCC", "GND": "GND", "IN": "IN"}},

    "ESP32-DevKitC-32E": {"type": "board-esp32-devkit-c-v4", "role": "mcu", "pin_style": "esp32"},

    "C": null
  },
  "board_pins": {
    "wokwi-arduino-uno": ["0", "1", "2", "…"]
  }
}
```

* Ключ — имя символа KiCad, полный `lib_id` или поле Value; можно шаблон с `*`. Ключи на `_`
  считаются комментариями.
* `pins` — пин KiCad (имя или номер) → пин Wokwi. Типы деталей и имена их пинов:
  <https://docs.wokwi.com/parts>.
* `pin_style`: `arduino` (`D13` → `13`), `esp32` (`IO2` → `2`, `TXD0` → `TX`), `pico` (`GPIO5` → `GP5`),
  `stm32` (`PA0` → `A0`). Все пины GND/питания сводятся к одному пину платы (`GND.1`, `5V` …).
* `null` вместо описания — деталь пропускается молча (так сделано для конденсаторов).
* `board_pins` — пины плат Wokwi; добавьте сюда свою плату, если подключаете её с `pin_style`.

Если в `mapping.json` ошибка JSON, экспорт остановится и покажет номер строки. Файл при этом
не перезаписывается.

Из коробки поддерживаются Arduino Uno/Nano, ESP32-WROOM-32 (как DevKitC v4), Raspberry Pi Pico / Pico W,
STM32F103C8 (как Blue Pill), светодиоды (включая RGB), резисторы (номинал из Value), потенциометры,
кнопки, переключатели, зуммер, сервопривод, DHT11/22, HC-SR04, OLED SSD1306, LCD 1602.

## Откуда берутся связи

По умолчанию (`NETLIST_SOURCE = "auto"`) плагин вызывает `kicad-cli sch export netlist`.
Связность тогда считает сам KiCad: иерархия, шины, метки — ровно как в ERC.
Если `kicad-cli` не найден, используется встроенный парсер `.kicad_sch`. Он понимает провода,
точки соединения, локальные, глобальные и иерархические метки, power-символы и вложенные листы,
но не шины, проходящие между листами. Детали с флагом «Исключить из платы» `kicad-cli` не
выгружает; если такие детали есть в `mapping.json`, плагин сам переключается на встроенный парсер.

## Запуск без KiCad (для отладки маппинга)

```bash
"C:\Program Files\KiCad\10.0\bin\python.exe" wokwi_exporter\wokwi_exporter.py D:\path\to\project.kicad_pro
```

Опции: `--source auto|kicad-cli|schematic`, `--layout grid|schematic`, `-o путь\diagram.json`,
`--mapping путь\mapping.json` (по умолчанию — рядом со скриптом), `--reset-layout`.

## Инструмент: каталог деталей Wokwi

`tools/update_wokwi_catalog.py` собирает `wokwi_catalog.json` — отсортированный список типов деталей
из публичных репозиториев Wokwi:

* `wokwi/wokwi-elements` — веб-компоненты, зарегистрированные через `@customElement('wokwi-…')` в `src/*.ts`;
* `wokwi/wokwi-boards` — платы, по папке на каждую: `boards/<имя>/board.json` — это тип `board-<имя>`.

```bash
"C:\Program Files\KiCad\10.0\bin\python.exe" tools\update_wokwi_catalog.py
```

Файл пишется в текущую папку. Скрипт показывает, сколько деталей появилось и исчезло с прошлого
запуска, и не трогает файл, если ничего не изменилось. Опции: `-o файл`, `--dry-run`, `--force`.

К API GitHub уходит по одному запросу на репозиторий, а сами файлы скачиваются с
`raw.githubusercontent.com` — это не расходует лимит API. Без токена GitHub даёт 60 запросов API
в час; переменная окружения `GITHUB_TOKEN` поднимает лимит до 5000. Нужен пакет `requests` — в Python
из KiCad он уже есть. Если структура репозитория изменится настолько, что детали не найдутся, скрипт
остановится и не перезапишет каталог.

У Wokwi есть и детали вне этих репозиториев — например, `wokwi-pi-pico` или `wokwi-logic-analyzer`, —
поэтому каталог не полный список того, что принимает `diagram.json`.

## Про API KiCad 10

В KiCad 10 SWIG-модуль `pcbnew` объявлен устаревшим в пользу нового IPC API, но всё ещё
поставляется (проверено на 10.0.7), поэтому плагин использует классический `pcbnew.ActionPlugin`.
Вся логика экспорта от `pcbnew` не зависит и работает из командной строки.
